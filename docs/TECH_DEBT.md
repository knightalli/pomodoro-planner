# Аудит и технический долг

Снимок состояния проекта: что уже хорошо, что болело и что с этим сделано.
Статусы: ✅ сделано · ⏳ осталось.

## Что хорошо (не ломать при рефакторинге)

- `scheduler.ts` — чистая логика без React: легко тестировать и переносить.
- Слои разделены: `platform.ts` — мост к ОС, `notifications.ts` — уведомления,
  `sound.ts` — звук, `storage.ts` — персистентность.
- Мягкие миграции в `loadStored()`: новые поля получают дефолты, старое состояние
  не ломается.
- Планировщик пересчитывается эффектом по изменению данных + `schedTick` раз в
  минуту — «просроченные задачи плывут вниз» без ручного вмешательства.

## P0 — критично: данные не персистились ✅

Было две независимые причины потери localStorage в десктопной оболочке
(в браузерном dev-режиме всё работало, поэтому баг был незаметен):

1. `webview.start()` без аргументов → `private_mode=True` (дефолт) → WebView2 в
   InPrivate, user-data в temp-папке, localStorage не пишется на диск.
2. `start_server()` биндился на случайный порт → origin новый при каждом запуске
   → localStorage партиционируется по origin.

**Исправлено** (`app.py`): `PORT = 31873` фиксированный → постоянный origin;
`webview.start(private_mode=False, storage_path=%APPDATA%\TimeTracker)` — свой
профиль на диске. Занятый порт трактуется как «уже запущено» → заодно
single-instance guard.

Проверка: запустить → создать задачу → закрыть через трей → запустить → задача
на месте.

## P1 — архитектура

### 1. `App.tsx` — монолит ✅

Было ~800 строк: 4 вкладки + настройки + тосты в одном компоненте. Разбит:
`App.tsx` — оболочка (нав-вкладки, попап итогов), вкладки в `src/components/`
(`TimerTab`, `PlannerTab`, `StatsTab`, `RemindersTab`, `SettingsPanel`, `Toasts`,
`TimeInput`, `TaskProgressBar`). Каждая получает `pomo: PomodoroApi` пропсом —
менялась только структура JSX.

### 2. `usePomodoro.ts` — god-hook ✅

Разделён на доменные хуки в `src/hooks/`: `useSettings` (настройки+автозапуск),
`useTimer` (секунды/перерывы/команды виджета), `usePlanner` (задачи, разделы,
фикс-дела, авто-расстановка), `useReminders`. `usePomodoro` — композиция +
кросс-доменные связки (`updateSettings`, `startTask`, persistence, daily-reset);
связь таймер→планировщик через коллбэк `onWorkElapsed(dt)`. Плюс ранее: dead
code удалён, `loadStored()` мемоизирован, настройки клампятся, daily-reset на
минутном тике.

### 3. Дублирование схемы состояния ✅

`StoredState`/`STORAGE_KEY`/`loadStored` жили в `usePomodoro.ts`, а `widget.tsx`
тащил урезанную копию с захардкоженными дефолтами. Вынесено в `src/storage.ts` —
оба окна импортируют одно и то же.

### 4. Виджет правил localStorage сырым JSON ✅

`toggleTracking` виджета дублировал семантику `stopTracking`. Теперь виджет
строго read-only: кнопки шлют `toggle`/`pause`/`resume` по
`BroadcastChannel("tt-commands")` (`bridge.ts`), единственный писатель —
главное окно.

### 5. Таймер считал секунды setInterval-тиками ✅

Переведён на timestamp-якоря: `workStartedAt` (начало рабочего сегмента) и
`breakEndsAt` (конец перерыва) — оба в `StoredState` с миграцией дефолтов в
`loadStored`. Тик — «сердцебиение»: `workStep(anchor, now, workSeconds,
threshold)` (чистая функция, покрыта тестами) досчитывает реально прошедшее
время; коммит ограничен остатком до перерыва. Сон/троттлинг больше не теряют
секунды. Виджет показывает «живые» значения по тем же якорям. Осознанно
сохранено: время закрытого приложения не учитывается — после перезапуска таймер
остановлен.

### 6. Daily reset только при маунте ✅

Теперь `applyDailyReset()` вызывается при маунте и каждые 60 c.
